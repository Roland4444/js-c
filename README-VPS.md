# Перенос калькулятора на VPS

Перенос реален: исходный архив содержит готовый HTTP-сервер Node.js и JSON-данные, без npm-зависимостей. Это калькулятор отделки с ролевым доступом, а не HTML-калькулятор план/факт из другого проекта. Формулы и интерфейс сохранены.

## Что изменено

Добавлен bitrix.js: загрузка SDK Bitrix24, BX24.init, user.current, выбор login по EMAIL/телефону/LOGIN/ID из предоставленного Lisp-фрагмента. login не используется как доказательство личности. Сервер проверяет access_token через user.current на фиксированном BITRIX_DOMAIN и получает ID сам. Заголовки X-Vibe-User-* больше не дают доступа. Неавторизованные запросы к данным и сохранению отклоняются.

После проверки выдается случайная сессия на час. Она хранится в памяти процесса, в браузере — в sessionStorage. Fetch передает ее заголовком; GET-форма — скрытым полем. Параметр удаляется из адресной строки после открытия страницы. Это позволяет обойти зависимость от сторонних cookie в iframe. Токен остается в сетевых URL GET-запросов: нельзя логировать query string на прокси/CDN. Referrer-Policy: no-referrer установлен. После часа или перезапуска нужен повторный вход (обновление страницы). Несколько процессов без общего хранилища сессий не поддерживаются.

Один URL приложения выполняет подключение SDK, BX24.init, BX24.installFinish и получение user.current, как в предоставленном Lisp-примере. Отдельного маршрута установки нет. Прямое открытие вне Bitrix показывает инструкцию, фиктивный пользователь не подставляется. GLPI-redirect, document.write и особая iOS-кнопка не перенесены: здесь приложение само является калькулятором.

ROLES_URL задается явно; без него используются роли из roles.json. DATA_DIR отделяет изменяемые данные от кода. Слушающий адрес по умолчанию 127.0.0.1.

## Развертывание

Потребуются Linux VPS, Node.js 22+, nginx, домен с HTTPS. Одна реплика приложения.

1. Распаковать код в /opt/calculator.
2. Создать системного пользователя calculator и каталог /var/lib/calculator с владельцем calculator.
3. Скопировать туда все JSON-файлы архива, сохранив исходные копии. Для действующего проекта сначала собрать также data.edited.json, sprav.edited.json, matrixk.edited.json, founder.json, если они существуют в Vibe. В этом архиве их нет; без них применяются исходные/встроенные значения. matrix.edited.json в архиве есть.
4. Скопировать deploy/calculator.env.example в /etc/calculator.env; указать реальный BITRIX_DOMAIN без схемы и пути, при необходимости ROLES_URL. Права файла 600.
5. Установить deploy/calculator.service в /etc/systemd/system/, затем systemctl daemon-reload и systemctl enable --now calculator.
6. Добавить deploy/nginx.conf внутрь HTTPS server-блока. Задать сертификаты, проверить nginx -t и перезагрузить nginx. Порт 3000 наружу не открывать.
7. В Bitrix24 создать локальное серверное приложение с интерфейсом: Путь обработчика https://romach.space/node/. Отдельный URL установки не нужен. Выдать доступ к данным пользователей (user.current). Открыть приложение в Bitrix и проверить имя и роли.
8. Проверить просмотр, пересчет, сохранение для каждой роли, импорт/удаление проекта и сохранность после перезапуска. Проверить отсутствие доступа у пользователя без роли.

Если прокси задает CSP, разрешить frame-ancestors только для вашего портала; убрать блокирующий X-Frame-Options. SDK загружается с api.bitrix24.com. VPS должен обращаться по HTTPS к вашему Bitrix и, при включении, к серверу ролей. Браузерные API-запросы используют относительные пути. Приложение работает в корне или под любым подпутём: nginx должен удалять префикс через завершающий / в proxy_pass, а URL приложения должен заканчиваться /. Все операции запуска приложения выполняются через один URL интерфейса.

## Риски исходного проекта

- ID 336 жестко получает роли 5, 6, 7 (отладка, матрицы, учредители). Перед запуском проверить, что это нужный сотрудник именно вашего портала.
- users.json содержит старый справочник имен: он имеет приоритет в заголовке. ID для прав приходит из подтвержденного Bitrix-пользователя.
- Запись JSON синхронная, ошибки сохранения подавляются исходными persist-функциями. Приложение может сообщить успех при ошибке диска. Для полноценной эксплуатации желательно атомарное сохранение, обработка ошибок и журнал изменений; эти изменения не включены в перенос.
- Импорт/сохранение исходного сервера не имеют общего ограничения тела в Node. nginx ограничивает запросы 10 МБ; распаковка gzip при импорте остается без ограничения размера результата. Импорт доступен привилегированной роли; нужен отдельный hardening при недоверенных администраторах.
- Запрет копирования/печати в браузере не защищает данные от пользователя, имеющего право просмотра.
- Сохраняется внешний вызов https://romach.space/lisp/hello при пересчете. Ошибки игнорируются и не блокируют расчет.
- Нужны резервные копии всего DATA_DIR, мониторинг свободного места и /healthz. JSON-хранилище подходит для одного процесса и небольшой нагрузки; для нескольких реплик нужна база.

## Проверка поставки

Проверена синтаксическая корректность обоих JS-файлов и локальные сценарии авторизации/доступа. Реальная установка, TLS, SDK в iframe и реальные роли требуют проверки на вашем портале; доступа к нему и VPS в этой сессии нет.



В калькуляторе отделки на Node.js предусмотрено 7 ролей:
Роль	Назначение	Возможности
1	Базовый просмотр	Калькулятор и итоговые значения без детализации состава отделки.
2	Подробный просмотр	Дополнительно виден состав отделки, без редактирования.
3	Себестоимость материалов	Просмотр детализации и изменение цен в составе отделки.
4	Стоимость работ и пакета	Просмотр детализации, вкладки «Расчёт» и «Справочник», редактирование стоимости работ/пакета.
5	Отладка	Выделение и копирование текста, кнопка «Скопировать», вкладка «Итог» со сводной калькуляцией по проектам.
6	Администрирование матриц	Редактирование объёмов, планировок, строк работ и коэффициентов ценообразования. Добавление, импорт и удаление проектов.
7	Учредители	Блок «Стоимость квартиры»: ввод стоимости продажи и первоначального взноса, расчёт цены без отделки за м².
